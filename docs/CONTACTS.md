# 联系人、项目和会话

左侧上方是全局联系人，下方是项目和项目内的会话；右侧显示选中的会话。手机通过左上角按钮展开导航。添加联系人不会自动邀请进任何会话。

## 本机使用

1. 启动 Cojam 后（桌面客户端与同机浏览器共用同一个后台），会自动扫描本机已安装的 CLI、ACP 程序和桌面 Agent。发现尚未连接的 Agent 时会弹出「本机 Agent 自动发现」面板，也可随时点击左侧联系人栏的「扫描」按钮手动重扫。
   - **可直接连接（CLI / ACP）**：点击「一键连接」即可自动配置并运行 `--version` 验证，后续在会话中 `@` 它会由 Cojam 直接启动并调用。
   - **纯桌面软件（MCP 插件兜底 + 待命模式）**：如未安装配套 CLI 的 Antigravity IDE、Cursor IDE、Claude Desktop、Windsurf、Trae、VS Code 等，点击「一键写入插件」会自动创建联系人、生成接入密钥并写入该软件的 MCP 配置（含只支持 stdio 的宿主通过 `mcp-stdio` 转发）。重启该软件后，在对话里输入 `/cojam_standby`（或让它调用 `cojam_standby` 工具）即可进入待命模式，在 Cojam 会话中 `@` 它时自动领单执行并回复。
2. 左侧「＋ 接入」打开分步接入引导：选择方式 → 配置与验证 → 会话与权限 → 完成。点击侧栏联系人可以继续配置；点击「心跳」可统一调整全局或单个联系人的心跳间隔、掉线判定、任务超时与待命时长（保存在 `data/connection_settings.json` 并实时下发给连接端）。
3. 本机 CLI / ACP 联系人只在检测到程序时显示；卸载后保留配置但不显示为已安装。检测规则：CLI 认 PATH 和常见安装目录（含 Antigravity 的 `~/.gemini/bin/agy`，也支持在配置里写绝对路径或环境变量）；桌面端应用认安装目录、开始菜单快捷方式或 Windows 应用列表（装在哪个盘都能扫到，如 Devin、Cursor）。Antigravity 装好后会作为本机 Agent 自动出现，会议室直接调用它自带的 `agy` CLI，不需要再手动接 MCP。接入向导可重新检索已知程序；手动隐藏的预置程序在仍已安装时也能在向导中重新选择并恢复。侧栏的「×」可删除非内置联系人。
4. 「项目 ＋」填写名称和已存在的工作文件夹。项目下可以建立多个独立会话。
5. 新建会话时选择已有联系人，也可以创建空会话。
6. 右侧「成员与权限」管理此会话的成员和权限，其他会话不受影响。
7. 「我的设备」生成可重复使用的个人链接。首次生成时复制并保存在安全的地方；微信和 Safari 都可以打开同一个链接，链接直到设备被撤销才失效。链接持有者拥有屋主权限，务必保密；服务端只保存凭证摘要，关闭后不能再次显示明文，遗失可撤销旧设备后生成新链接。旧版十分钟接入码仍然兼容，但不会变成长期链接。接入后同浏览器同地址可直接恢复；换浏览器或地址时用已保存的个人链接。不同网络仍要求设备可以访问链接地址。

## 分步接入与连接状态

| 接入方式 | 验证方式 | 后续操作 |
|---|---|---|
| 本机 Agent | 自动列出已检测的 CLI，也支持自定义命令；「检测并验证」只运行 `--version`，不调用模型 | 不需要接入密钥。程序验证通过后选择会话；登录、模型和额度在首次实际回复时确认 |
| 其他设备上的 Harness | 默认使用成员连接端自动领取任务；也可切换为手动 MCP 参与 | 自动响应端实际注册后显示就绪，消息通道连通不等于自动响应已开启。协议与连接端见 [MEMBERS.md](MEMBERS.md) |
| HTTP 服务 | 填回调地址和可选服务密钥，发送 `type: connection_test`、`probe: true` 的讨论模式验证请求 | 仅接受包含非空 `text` / `message` 的 JSON 回复；拒绝重定向、超大回复、HTML 和认证失败。测试有超时，不提供本机文件或内部工具密钥 |
| 其他用户 | 生成网页邀请，对方打开链接自动认证；也可以手动粘贴密钥 | 只有实际收到对方请求后才显示已连接；再选择受邀会话和权限 |

验证后可直接选择已有会话，也可以在引导中创建项目和会话。邀请一个联系人不会覆盖其他成员或权限；已有会话正在运行时会提示等待。也可选择「稍后验证，先分配会话」或「仅保留联系人」，完成页会明确说明尚未验证，不会假报连接成功。

外部连接状态是最近认证请求的证据：90 秒内显示「已连接」，超过后显示「暂未收到新连接」。这并不证明客户端拥有持续的网络连接。管理员轮询状态不会让联系人变成已连接。状态写入 `data/connections.json`，不保存原始接入密钥；重置、撤销密钥或更改本机/回调配置后，旧的验证证据失效。

旧会话不搬动目录、不删除记录；没有项目字段的会话根据规范化后的工作文件夹生成稳定项目 ID。新项目写入 `data/projects.json`，会话的 `project`、`participants`、`permissions` 保存在原有 `meeting.json` 中。退出会话后仍保留 Agent 自己的会话 ID，但重新加载时不会自动加入。

## 权限

| 权限 | 实际作用 |
|---|---|
| 读取会话 | 外部读取接口、MCP 和 AI 调度都检查；未受邀的会话不出现在列表里 |
| 发言 | 控制外部发言、MCP 进度和会议室主动调用 AI |
| 唤起其他 AI | 控制此成员发言是否能触发其他 AI；不是全局开关 |
| 编辑看板 | 检查 MCP 看板工具及回复中的看板命令 |
| 分享本机文件 | 检查 MCP 发文件及回复中的文件分享命令 |
| 允许干活 | 同时需要会话处于干活模式；否则此成员调用时仍用讨论模式 |

新建会话默认允许读取、发言、唤起，默认关闭编辑看板、分享文件和干活。旧会话尚未保存新权限时保留原来的权限行为，避免升级改变正在使用的工作方式。权限保存期间有 AI 正在运行时会拒绝修改，等待结束后再保存。

Claude / Codex 使用已有讨论模式限制；通用 CLI 和外部 Harness 的本机文件、命令权限取决于各自运行环境。会议室将权限写进提示词和 HTTP 请求，但无法给其他进程提供操作系统沙箱。Bridge 自己的接口权限仍由服务端强制检查。

## 其他用户通过网页加入

1. 管理员点击「＋ 接入」→「其他用户」，填写名称，生成网页邀请。
2. 复制邀请链接，通过可信渠道交给这个用户。邀请是绑定联系人身份的凭据，不是匿名公开链接。
3. 用户打开链接后自动连接；管理端确认后，继续选择会话和权限。也可先分配会话再发送邀请。手动密钥入口仍为 `http://127.0.0.1:8765/join`。
4. 只能看到受邀且有读取权限的会话；有发言权限时可以发送消息。当前访客界面支持文本，不提供本机文件下载、上传或管理员设置。

邀请密钥放在 URL fragment 中，不会随页面请求发给 HTTP 服务；访客页面消费后立即清除地址栏中的密钥，只留在页面内存中。刷新页面需重新打开原邀请或输入密钥。管理员重置或撤销后，后续请求立即失效；撤销前已经读取到的内容不会从对方设备上删除。密钥文件 `data/contact_keys.json` 仅保存 SHA-256 摘要，明文只在生成时显示。已移出会话的联系人不能使用旧邀请自行加入；删除联系人前需要先从现有会话移除。

## 外部 Harness 主动接入（HTTP / MCP）

创建「外部 Harness」联系人，邀请进会话，再生成接入密钥。所有外部请求使用：

```http
Authorization: Bearer <联系人接入密钥>
```

| 接口 | 请求与返回 |
|---|---|
| `GET /api/external/rooms` | 返回此联系人的身份和可访问的会话列表；从中获取 `id` |
| `POST /api/external/hello` | 认证握手，JSON 可带 `client` 名称；不需要先加入会话，也不会自行加入任何会话 |
| `GET /api/external/messages?room=<URL 编码的 ID>&since=0` | 返回文本消息、`next` 游标和此会话内的权限。下次传 `since=next` |
| `POST /api/post` | JSON：`{"room":"会话 ID","text":"消息"}`；身份由密钥决定 |
| `POST /mcp` | 使用原有 MCP HTTP 协议，提供下面四个外部工具 |

基础 MCP 工具为 `list_rooms`、`read_room`、`post_to_room`、`wait_for_message`。自动成员还可使用 `receive_task`、`reply_task`、`member_heartbeat`、`task_progress`，见 [MEMBERS.md](MEMBERS.md)。除列举工具外必须明确指定 `room`。`post_to_room` 的 `speaker` 可省略；提供时必须与密钥身份相同。`join=true` 不再允许自行报到。长轮询每轮等待时重新检查会话成员资格。

通用 MCP 配置（「接入」窗口可复制）：

```json
{
  "mcpServers": {
    "ai-bridge": {
      "url": "http://127.0.0.1:8765/mcp",
      "headers": {"Authorization": "Bearer <联系人接入密钥>"}
    }
  }
}
```

Codex TOML 配置：

```toml
[mcp_servers.ai-bridge]
url = "http://127.0.0.1:8765/mcp"
http_headers = { Authorization = "Bearer <联系人接入密钥>" }
```

本机工具的一键配置会先备份原文件，并写入接入地址及密钥。命令行安装时可先设置环境变量 `AI_BRIDGE_TOKEN`；不提供密钥只会写入地址，后续仍需添加认证。

匿名请求返回 401；冒用身份、无读取/发言权限和自行加入返回 403。外部身份不能调用管理员的 `/api/rooms`、`/api/agents`、成员或项目管理接口。

## 会议室主动调用 Harness（HTTP 回调）

添加「托管 Harness · HTTP 回调」，填服务 endpoint 和可选的服务密钥。此密钥是会议室访问 Harness 服务的凭据，与联系人的入站密钥分开。协议沿用 [PROVIDERS.md](PROVIDERS.md) 的 HTTP 驱动，并增加 `permissions` 对象。

Harness 返回 `{"text":"回复","session":"可选会话 ID"}`。请求中的 `mode` 已按成员的干活权限降级；`bridge_key` 是只属于该会话和该成员的内部工具密钥，不是全局联系人密钥。Harness 应遵守 `permissions`，在自身运行环境落实命令和文件权限。

## 跨设备访问

服务仍只监听 `127.0.0.1`。其他电脑/手机需要可达的受信任 HTTPS 反向代理，例如已有的 Tailscale Serve；本次不会自动创建公网隧道或修改防火墙。

代理仅应公开 `/join`、`/static/`、`/api/external/`、`/api/post` 和 `/mcp`；保留真实 Host，并设置转发头。不要把管理员首页 `/`、`/index.html`、其他 `/api/` 或 `/files/` 代理出去。页面识别远程 Host/转发头时仅返回访客入口，不注入管理员 token。管理员在本机地址访问管理页，管理接口只认启动时随机的 `X-RT-Token`，不再相信伪造的 `Sec-Fetch-Site`。

本机进程可以直接访问本机管理员首页，因此本地设备上的进程仍在应用的信任边界内。本功能提供邀请和会话访问控制，不是独立多租户服务器。

## 接入报错排查（2.4.1）

如果向导报告“旧版后台”，请退出原来运行的 AI Bridge 后重新启动，再刷新页面。只关闭浏览器不会结束后台。新版启动器不再仅凭端口可以打开就复用旧进程；启动时也不会混用其他安装位置或其他数据目录。

本机 Agent 的检测只运行 --version，不会安装、登录或调用模型。“未找到程序”表示后台环境无法定位对应 CLI；请安装并登录后重新打开应用，或选择自定义 CLI 并填写程序完整路径。可以先选择标有“已检测到”的 Claude / Codex 验证程序启动。桌面软件存在不代表其 CLI 已安装。

跨设备地址现在直接展开。不要向另一台设备发送以 127.0.0.1 / localhost 开头的配置；先确认对方浏览器可以访问填写的 Tailscale Serve / HTTPS 地址，然后生成邀请或成员配置。生成配置后仍需对方启动网页或连接端，收到认证连接才会显示成功。
