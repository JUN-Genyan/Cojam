# 本机 Harness 扫描与连接改版方案

状态：待验证，不改变现有默认流程。

目标：把「接入 → 连接 AI → 本机 Agent」从一张需要理解实现细节的配置表，改成一次扫描、按结果分组、每行只有一个明确动作的连接流程。CLI 程序和桌面应用都在同一个结果页里出现，但不会把「检测到图标」说成「已经能调用」。

范围：本方案只处理运行 Cojam 后台的这台电脑上的本机 Harness。手机 / 其他电脑的接入仍走「我的设备」二维码流程；远程成员上报的 Harness 能力继续由成员协议提供，不在本机扫描结果里伪装成可直接调用的程序。

## 1. 现在的问题

结合当前实现（`bridge/discovery.py`、`bridge/registry.py`、`static/connections.js`）和实际使用：

1. **扫描入口藏得深。** 要先进入接入向导、选择「连接 AI」、再选择「本机 Agent」才会触发扫描；用户不知道这一步会做什么。
2. **结果混在一起。** 可调用的 CLI、已安装但只能作为外部成员的桌面应用、被隐藏的预置联系人共用一套「联系人」概念；列表里只写「已检测到」，没有说明「检测到什么、能不能直接干活」。
3. **桌面应用是死路。** 点「配置 Cursor」后仍然要理解 MCP / HTTP / 外部成员，最后发现会议室不能直接调用它；用户会认为扫描失败或产品在骗人。
4. **多个安装不直观。** 同一程序有多个版本时，安装选择藏在模型目录加载之后的下拉框里；扫描阶段看不到路径和版本。
5. **扫描过程不透明。** 后台扫描只显示「正在后台检索其他安装入口」，没有已发现数量、当前阶段、失败原因；「重新检索」后列表整体重绘，容易丢失当前选择。
6. **失败没有出口。** 没检测到、版本命令超时、程序路径失效时，只能反复点「重新检索」或自己猜「自定义 CLI」怎么填。

## 2. 设计原则

- **一次扫描，一个结果页。** 打开「本机 Agent」立即开始扫描，结果分批出现，不需要先点按钮。
- **按「能不能用」分组，不按「是什么驱动」分组。**
- **每行一个主 action。** 主按钮之外只保留「选择安装」「诊断」这类次 action。
- **桌面应用说实话。** GUI 应用本身不能被会议室调用；能接的是它自带的 CLI，或它支持的 MCP / HTTP。界面必须明确写出区别。
- **连接是原子的。** 选安装、建联系人、加入会话一次完成；失败时保留用户输入和选择。
- **恢复优先。** 每个失败状态都给出下一步：重试、手动选程序、复制诊断、查看日志。

## 3. 目标流程

### 3.1 入口

「接入」→「连接 AI」→「本机 Agent」后直接进入扫描页：

```
┌─ 连接本机 AI ─────────────────────────────────────────────┐
│ 在这台电脑上查找可以协作的 AI                              │
│ 正在扫描 · 已找到 3 个程序、2 个桌面应用        [停止扫描] │
│ ██████████████████████░░░░  78%                            │
│                                                            │
│ 可以直接连接                                               │
│ ┌────────────────────────────────────────────────────────┐ │
│ │ Claude Code      2.1.4    PATH                    [连接] │ │
│ │ Codex            0.52.0   C:\...\codex.exe        [连接] │ │
│ │ OpenCode         2.2.5    2 个安装               [连接] │ │
│ └────────────────────────────────────────────────────────┘ │
│                                                            │
│ 需要确认                                                   │
│ ┌────────────────────────────────────────────────────────┐ │
│ │ Qoder CLI        版本读取超时                     [诊断] │ │
│ │                  C:\...\qodercli.exe        [仍然连接] │ │
│ └────────────────────────────────────────────────────────┘ │
│                                                            │
│ 桌面应用（不能直接接收任务）                               │
│ ┌────────────────────────────────────────────────────────┐ │
│ │ Cursor           已安装 · 自带 Agent CLI 已找到          │ │
│ │                  C:\...\Cursor.exe       [连接 CLI]     │ │
│ │ Devin            已安装 · 未找到可用 CLI                 │ │
│ │                  [作为外部成员接入] [查看接入方式]       │ │
│ └────────────────────────────────────────────────────────┘ │
│                                                            │
│ 没找到？ [手动选择程序] [重新扫描] [复制诊断信息]           │
└────────────────────────────────────────────────────────────┘
```

### 3.2 连接确认

点「连接」后不跳页，弹一个紧凑确认层：

```
连接 Claude Code
安装：C:\Users\...\claude.exe（2.1.4）
名称：[我的 Claude          ]
加入：[当前会话 ▾] [暂不加入]

[取消] [连接]
```

连接成功后：

- 行状态变为「已连接」，主按钮变为「打开」或「已加入会话」。
- 顶部 toast：「已连接 Claude Code，并加入「登录页改版」」。
- 如果选择「暂不加入」，联系人保留在列表里，可稍后从会话里添加。

### 3.3 多个安装

有多个真实安装时，不默认藏在下拉框里。行内直接显示：

```
OpenCode  2.2.5 · 2 个安装                    [选择安装 ▾] [连接]
  ○ C:\Users\me\AppData\Roaming\npm\opencode.cmd
  ● C:\Tools\opencode\opencode.exe   （当前）
```

选择安装后立即记住，连接时使用该路径；同一程序的不同 shim 不重复计数。

### 3.4 桌面应用

桌面应用分三种情况，界面文案必须不同：

| 情况 | 行内文案 | 主 action |
|---|---|---|
| 找到同品牌 CLI | 「已安装 · 自带 CLI 已找到」 | 连接 CLI |
| 只有 GUI，支持 MCP/HTTP | 「已安装 · 可通过外部成员接入」 | 作为外部成员接入 |
| 只有 GUI，没有可用接口 | 「已安装 · 会议室不能直接调用」 | 查看接入方式 |

「作为外部成员接入」复用现有外部成员流程，但入口从桌面应用行直接进入，并预填应用名称；不再要求用户先理解「会外参与者」。

### 3.5 扫描失败 / 没找到

- 扫描阶段失败：显示阶段名和原因，例如「读取开始菜单快捷方式失败：权限不足」，提供「重试此阶段」。
- 单个程序探测失败：该行进入「需要确认」，不影响其他结果。
- 完全没找到：显示「没有检测到可调用的程序」，并给三个出口：
  - 「手动选择程序」：文件选择器，选完直接探测版本。
  - 「安装说明」：打开对应 Harness 的安装文档。
  - 「复制诊断信息」：包含平台、PATH 摘要、扫描阶段、错误，不包含密钥。

## 4. 状态模型

每个候选用一个状态，前端只根据状态决定文案和按钮：

| 状态 | 含义 | 主 action |
|---|---|---|
| `ready` | 找到可执行文件，版本探测成功 | 连接 |
| `attention` | 找到文件，但版本/帮助命令失败或超时 | 仍然连接 / 诊断 |
| `desktop_cli` | 桌面应用，且找到同品牌 CLI | 连接 CLI |
| `desktop_external` | 桌面应用，支持 MCP/HTTP | 作为外部成员接入 |
| `desktop_only` | 桌面应用，没有可用接口 | 查看接入方式 |
| `connected` | 已经是联系人，且安装有效 | 打开 / 已加入 |
| `missing` | 之前连接过，但程序已被卸载 | 重新扫描 / 手动指定 |

扫描本身的状态：`idle` → `scanning` → `done` / `partial` / `error`。`partial` 表示至少一个阶段失败，但其他结果可用。

## 5. 数据与接口

### 5.1 候选结构

```json
{
  "id": "opencode",
  "label": "OpenCode",
  "kind": "cli",
  "status": "ready",
  "version": "2.2.5",
  "source": "package",
  "installations": [
    {"id": "a1b2c3", "path": "C:\\...\\opencode.exe", "version": "2.2.5", "selected": true}
  ],
  "linked_cli": null,
  "evidence": {"checked_at": "2026-11-10T10:00:00Z", "version_command": ["--version"]},
  "actions": ["connect", "choose_installation", "diagnose"],
  "note": ""
}
```

桌面应用示例：

```json
{
  "id": "cursor_desktop",
  "label": "Cursor",
  "kind": "desktop",
  "status": "desktop_cli",
  "version": null,
  "installations": [{"id": "d4e5f6", "path": "C:\\...\\Cursor.exe"}],
  "linked_cli": "cursor_agent",
  "actions": ["connect_cli", "connect_external"]
}
```

### 5.2 扫描接口

新增 `GET /api/agents/scan`，返回当前快照：

```json
{
  "scan_id": "scan-...",
  "state": "scanning",
  "phase": "desktop_shortcuts",
  "progress": 0.78,
  "started_at": "...",
  "finished_at": null,
  "candidates": [],
  "counts": {"ready": 3, "attention": 1, "desktop": 2, "connected": 1},
  "errors": []
}
```

`POST /api/agents/scan` 开始新扫描；重复调用返回当前 `scan_id`，不并行启动。前端每 500ms 轮询，或复用现有 `/api/agents` 的轮询节奏。

兼容策略：保留现有 `/api/agents`、`discovered_presets`、`/api/agents/restore`，新页面先用新接口；旧页面不受影响。

### 5.3 连接接口

新增 `POST /api/agents/connect`：

```json
{
  "candidate": "opencode",
  "installation": "a1b2c3",
  "label": "我的 OpenCode",
  "room": "room-id-or-empty"
}
```

服务端原子执行：

1. 校验候选和安装仍然有效（重新探测一次路径）。
2. 选择安装。
3. 创建或恢复联系人。
4. 如果给了 `room`，把联系人加入会话。
5. 返回联系人、安装和会话状态。

失败返回 409/400，并保留前端已填的名称和选择；前端只重试失败步骤，不重绘整页。

## 6. 扫描实现建议

- **分阶段发布快照。** `PATH / App Paths` 先出结果，随后注册表、包入口、开始菜单快捷方式逐步合并；每个阶段结束时更新快照，前端不必等全部结束。
- **限制探测。** 每个版本/帮助命令 8 秒超时，最多 2 个并发（沿用现有 `PROBE_LIMIT`）。
- **不启动 shell。** 继续使用现有 `discovery.py` 的直接执行和 shim 解析逻辑，不执行 `.cmd` 内容。
- **去重。** 同一 `.cmd`/`.ps1` shim 与目标 `.exe` 算一个安装；同一路径的大小写和符号链接归一化。
- **桌面应用检测。** Windows 继续读开始菜单有效快捷方式和 App Paths；macOS 读 `/Applications` 和 `~/Applications`；Linux 读 `.desktop` 文件。只做文件存在性和目标解析，不启动 GUI。
- **同品牌 CLI 关联。** 预置里增加 `linked_cli` 字段（例如 `cursor_desktop` → `cursor_agent`），扫描完成后把 CLI 候选挂到桌面应用行；没有 CLI 时不伪造。
- **缓存。** 扫描结果内存缓存 60 秒；「重新扫描」强制刷新。版本探测结果单独缓存 5 分钟，按路径 + mtime 区分。

## 7. 前端实现建议

- 新页面放在 `static/connections.js` 的独立模块里，先用 `?scan=2` 或设置项开关，验证后再设为默认。
- 结果列表用稳定 key（候选 id + 安装 id）渲染，扫描更新时只更新变化的行，不整表重绘；保留滚动位置和展开状态。
- 主按钮在请求期间显示「连接中…」并禁用；失败后在行内显示错误，不用全局 alert。
- 桌面应用行不显示「连接」按钮，避免用户误以为能直接调用 GUI。
- 键盘：Tab 可到达每个 action；Enter 触发主 action；Esc 关闭确认层。
- 无障碍：状态用文字，不只靠颜色；扫描进度用 `aria-live="polite"`。

## 8. 验证原型

本方案附一个静态原型：`docs/prototypes/harness-scan.html`。它不连接后端，用假数据演示：

- 扫描中的进度和分批结果；
- 可直接连接 / 需要确认 / 桌面应用三组；
- 多安装选择；
- 连接确认层和成功状态；
- 桌面应用的三种文案；
- 空结果和扫描失败状态；
- 「重新扫描」「手动选择程序」「复制诊断」入口。

验证时重点看：

1. 第一次使用的人能否在 30 秒内完成一次连接。
2. 看到桌面应用行时，是否理解「不能直接调用」以及下一步是什么。
3. 多个安装时，是否知道当前选的是哪一个。
4. 扫描失败或没找到时，是否知道该点哪里。
5. 连接失败后，已填名称和选择是否还在。

## 9. 分阶段落地

1. **后端快照（不改 UI）**：实现扫描状态、候选结构、`/api/agents/scan`、`/api/agents/connect`，补单元测试；旧接口保持兼容。
2. **原型验证**：用静态原型和真实扫描数据做对照，确认分组、文案、action 是否符合预期。
3. **新 UI 灰度**：`?scan=2` 开关接入真实接口；保留旧流程作为回退。
4. **默认启用**：验证通过后设为默认，旧流程只保留一个版本周期。
5. **清理**：移除 `discovered_presets` 在 UI 里的直接使用，统一走候选模型；文档同步更新。

## 10. 已确认的决策（2026-11-10）

- 桌面应用「作为外部成员接入」：**单独做一条简化流程**，不复用现有外部成员向导；入口在桌面应用行内，预填应用名称。
- 连接后**必须显式选择**加入哪个会话；确认层默认「暂不加入」，不自动加入当前会话。
- 扫描日志区**始终显示**，实时列出各阶段；「复制诊断」放在日志区旁。
- 同一品牌同时有桌面应用和 CLI 时，按设备暂时只视作一个条目，延续现有「一个程序一个联系人」的思路，合并为一行，主 action 连接 CLI。
