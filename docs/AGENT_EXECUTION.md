# Agent 执行端与模型（2.8.0）

## CLI 与桌面

联系人保存 CLI 与桌面 MCP 配置；各会议中的每位 Agent 独立选择执行端。CLI 由合拍直接启动；桌面由 MCP 待命循环接单，心跳过期即显示离线。扫描只提供候选程序，点击「配置 CLI」或「配置桌面 / MCP」都打开同一套可反复编辑的设置页。

桌面在线不会抢占 CLI，桌面离线也不会自动切回 CLI。既有普通外部 Harness、HTTP 服务和网页访客继续使用原协议；不会按软件品牌合并已有联系人 ID。

## 共享同一原生会话

点击会议中 Agent 的状态卡，在「执行端」选择「由桌面接管同一会话」。当前实现提供 Claude / Codex 原生日志适配，接管时逐条验证，而非仅凭产品名声明支持。尚无适配的软件保留当前执行方式，不新建另一条会话代替原生续接。

1. 先在 Agent 设置中应用桌面 MCP 配置。会议不能有运行、排队、压缩或交给终端的任务。
2. 若会议显式选择了模型或 effort，先明确恢复会议默认值。普通桌面 MCP 没有模型写入接口，接管不能静默丢弃指定设置。
3. 点击桌面接管后，CLI 调度和原 CLI 的工具读取暂停。界面生成五分钟有效的接管指令；Claude 还可复制使用已配置 CLI 路径打开原生会话的命令。
4. 在桌面打开同一条原生会话，发送接管指令，让它调用 `cojam_standby`。服务端核对原生 ID、本机工作目录，以及该原生日志中实际助手工具调用携带的一次性凭证。用户消息里粘贴的工具示例不能作为证明。Codex 的直接 MCP 调用和工具编排调用均可识别。
5. 验证通过、会话专属 worker 注册完成后才发布就绪状态。后续待命需携带返回的 `room/worker/binding_token` 和原生 ID。一个联系人可以在不同会议绑定不同桌面原生会话，领取任务时只看自己的会议。

切回 CLI 时，在线桌面先收到释放请求，再用 `release_session` 确认并停止待命；原生 ID 保持不变。桌面已离线且没有任务时，可以显式切回已配置的 CLI。未完成的交接可以取消，五分钟超时恢复原执行端。后台重启不会重放旧任务，也不会自动改换执行端。

同一原生会话不能重复绑定给其他会议或联系人。更换执行端带有版本检查，旧端迟到的回复与读取被拒绝。桌面读取会话需要联系人凭据和会话专属执行端凭据；只持有联系人密钥不能读到由 CLI 占用或由另一桌面会话占用的记录。

这些约束覆盖合拍接口及调度，不阻止用户在厂商软件中手动打开本地记录。跨电脑不同原生存储不能通过复制会话 ID 冒充同一会话；没有实际共享原生记录时拒绝接管。

## 在会议室切换模型与 effort

Agent 状态卡提供模型选择、按模型联动的 effort、刷新索引和应用状态：

- Codex 刷新通过实际 CLI 的 `model/list` 获取模型与 reasoning 选项，不创建会话、不发送模型任务。启动参数变化后使用独立索引。
- ACP 刷新读取握手后会话声明的配置选项，按工作目录隔离缓存。设置使用真实配置项 ID；拒绝时停止本轮，不静默改回默认值。
- 没有统一枚举接口的 CLI 使用应用内可编辑索引和参数模板。账户可用性以执行端实际接受为准。
- 索引保存上次成功结果及来源、时间；重启可恢复。刷新失败保留列表并显示过期或错误，不能把失败当成「不支持」。
- 「已选择，待下一轮应用」「执行端已接受」「设置应用失败」分别显示。原生记录能够回报时，另显示实际模型和 effort；不能把用户选择当成实际回报。
- 普通桌面 MCP 不具备改变宿主模型的接口，因此保留接入及任务处理，并只读展示原生会话实际模型，限制模型/effort 控件。不会靠向模型发提示词假装完成切换。后台不会代替用户改厂商软件的全局模型配置。

运行、排队和执行端交接期间不能改模型。不同会议的选择互不影响；联系人默认值只用于未显式覆盖的设置。

## 接口兼容

后端版本为 2.8.0，管理 API revision 为 3；HTTP 成员协议仍为 v1，并增加可选字段。

| 接口 | 用途 |
|---|---|
| `GET/POST /api/agents/config` | 读取和保存交互设置，包含配置版本检查 |
| `POST /api/agents/config/mcp` | 事务式应用 MCP，显式确认密钥更换，失败恢复原配置 |
| `POST /api/discovery/prepare` | 将扫描候选引入统一设置；不覆盖已有驱动 |
| `POST /api/r/{room}/execution` | `ai/endpoint/version` 准备交接；`op=cancel` 取消 |
| `GET /api/r/{room}/models/catalog?ai=…` | 当前执行端索引、来源、应用状态及实际回报 |
| `POST /api/r/{room}/models/refresh` | 刷新模型索引，不生成模型回复 |
| MCP `cojam_standby` | 增加 room/native_session/binding_challenge，后续使用 worker/binding_token |
| MCP `release_session` | 释放原生会话给 CLI，成功后结束待命 |

HTTP 外部读取使用 `X-Cojam-Worker` 与 `X-Cojam-Execution` 传递会话执行端凭据，不能放进 URL。MCP 读取工具使用 `worker/binding_token` 参数。任务回复仍校验 lease，且不得改写共享原生会话 ID。

升级不删除会话、已有模型会话、权限和密钥；没有新绑定的本机联系人默认 CLI，普通外部成员沿用原执行协议。原先依靠「在线就优先桌面」的本机联系人需在会议中显式接管。

## 本次验证

2026-11-13 完整隔离回归 374 项通过。之后补充并单独复核：扫描模块 7 项、界面模块 22 项、模型索引 8 项、成员协议 18 项均通过，覆盖残留 MCP 文件、验证失败误报、写入失败保留旧配置、迟到界面响应和远端恢复默认模型。

本机实际 Codex `model/list` 查询返回 8 个模型，确认了模型及 reasoning 选项字段；未创建会话或发送模型任务。原生日志适配对照了本机 Claude / Codex 的记录结构，接管流程使用隔离日志、假 Agent 和独立服务验证。Chrome 实际页面验证覆盖模型刷新、待应用状态、接管凭证、读取隔离、释放回相同会话、取消与手机布局；不能据此宣称所有厂商或所有版本都已实测。
