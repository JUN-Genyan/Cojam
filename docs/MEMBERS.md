# 一个会议室，统一的成员

AI Bridge 保存项目、会话、成员名单和授权。人和 Harness 加入同一会话；Harness 在哪台设备上运行，不改变消息路由、排队、回复和互相 @ 的规则。

本机 CLI、直接调用的 HTTP Harness 和其他设备的成员连接端共用 `Room.enqueue → process_job → drivers.call → handle_message` 调度链。用户消息可以并行唤起成员；成员之间通过 @ 串行接续；每个成员在每场会话中的调用保持串行。人类联系人可以发言，但不会被作为 AI 调用。

## Windows 与 MacBook 协作

1. 在公司 Windows 上启动会议室服务，接入公司 Harness。
2. 添加「其他设备上的 Harness」联系人，选择「自动接收任务并回复」，生成连接配置。
3. 在个人 MacBook 打开成员连接端，导入该配置，选择个人 Harness 和 Mac 本机项目文件夹。
4. 会议室显示「自动响应已连接」后，把它加入目标会话，设置权限。
5. 公司成员 @ Mac 成员时，任务在 Mac 上执行并回复同一会话；回复中的 @ 可以继续叫公司成员。手机仍可通过同一服务参与。

Windows 完整包提供 `连接其他会议室.bat`（调用 `AIBridge.exe member-ui`）。便携源码连接端支持 Windows / macOS 的 Python 3.11+，图形窗口还需要 Tk。macOS 提供 `start-member.command`，也可执行 `python3 -m bridge.member_ui`。目前不是签名的原生 Mac 应用，且未在真实 Mac 设备验证。

连接端包可从接入窗口下载；其中不包含会话、运行数据或接入密钥。配置 JSON 包含密钥，需单独交给对应成员。连接端可导入本机 CLI / HTTP 驱动配置。只能操作聊天窗口、没有可调用接口的桌面 Harness，仍需要专用适配。

## 自动响应与普通 MCP

普通 MCP 的 `list_rooms / read_room / post_to_room` 保留，适合主动查看与发言。仅配置这几个工具不会凭空启动模型；应开启成员连接端，或让 Harness 通过新工具持续领取任务。

MCP 增加：

| 工具 | 含义 |
|---|---|
| `receive_task` | 用稳定的 worker ID 注册自动响应端，长轮询最多 20 秒，领取任务 |
| `reply_task` | 携带任务 id 和 lease 提交结果，由会议室统一入库并处理 @ |
| `member_heartbeat` | 每 10 秒续连接，任务执行时带 task 和 lease 检查取消 |
| `task_progress` | 当前任务的中途发言，不触发其他成员 |

不同 Harness 使用不同联系人 ID。同一个身份只允许一个活跃的自动响应端。消息通道连上与自动响应端连上是两个可观察的状态，不会因管理员轮询或复制配置而假报就绪。

## HTTP 成员协议 v1

所有请求均为 POST JSON，并使用 `Authorization: Bearer <此成员密钥>`。身份由密钥决定，不接受 speaker 冒用。入口为 `/api/external/member/<action>`。

| action | 参数 / 结果 |
|---|---|
| `connect` | `worker`、`device`、`workdir`、布尔值 `allow_work`；返回 member 身份和心跳间隔 |
| `receive` | `worker`、`timeout`（0–20）；返回 `task: null` 或任务 |
| `heartbeat` | `worker`；执行时还带 `task` 和 `lease`，返回当前状态 |
| `reply` | `worker`、`task`、`lease`、布尔值 `ok`、非空 `text`、可选 `session` |
| `progress` | `worker`、`task`、`lease`、`text`；记录中途进度，不处理 @ |
| `live` | 相同租约与 text，更新状态条中的临时输出，不写会话消息 |
| `board` | 相同租约与 `op/kind/text/ids`，另外检查此成员的看板权限 |
| `disconnect` | `worker`，停止此身份的连接及在途任务 |

任务包含 `protocol/id/room/member/title/goal/prompt/session/mode/permissions/model/effort/board/execution/lease`。它不含会议室管理员 token、全局联系人密钥、宿主文件句柄或宿主内部工具钥匙。

`reply` 是任务完成，不要再用 `post_to_room` 重复发送同一最终回复。相同任务、租约和结果可重复提交以恢复丢失的确认；不同结果不能覆盖已完成任务。`receive` 重试可返回同一个已领取任务，执行端必须缓存任务回执防止重复执行。

## 权限与执行位置

- 所有任务都检查当前成员资格、读取和发言权限；受邀范围之外的会话不分发给该成员。
- 干活权限取「会话模式 ∩ 会话成员权限 ∩ 本机连接端允许干活」。默认连接端只讨论。
- 本机工作目录由连接端选择，会议室任务不能将它替换成另一台设备的路径。
- 各设备代码与文件不会自动同步。跨设备附件传输、远端编辑撤回尚未实现；远端回复中的文件命令不会拿去读取会议室宿主文件。
- 远端任务不对会议室宿主仓库拍快照或撤回。CLI 子进程使用本地作用域的工具钥匙，联系人网络密钥不放进模型提示词，也从子进程继承环境中移除。
- 本地文件护栏在执行设备运行，共享看板与进度通过任务租约回到原会话。任意第三方 CLI / HTTP 服务仍需自行落实操作系统权限。

## 停止、失联与恢复

连接端在执行期间持续发心跳；停止、撤销凭据、取消任务、成员连接过期时会拒绝迟到的结果与后续 @。本地 CLI 会尽力终止；已经修改的文件不会回滚，已调用的外部 HTTP 服务可能仍需在该服务侧停止。

失联任务不自动重新分配，会议室重启也不重放旧任务，避免重复执行有副作用的工作。需要时由用户重新发起任务。连接端为任务保留本机回执：结果已完成时可重新提交，执行中途异常退出则报告失败，不偷偷再调用一次模型。

会话消息仍在服务端 `data/meetings`，任务元信息写入 `data/member_tasks.json`（不含 prompt）。连接端将身份标识、独立会话映射和回执存入 `~/.ai-bridge/member`，不保存原始网络密钥。用户下载的连接配置文件需自行妥善保管。

## 网络与验证

本次提供跨设备成员执行协议及连接端，网络仍需要可达的服务地址，可继续使用 Tailscale / 公司批准的网络。连接端主动连接服务端，不要求开放执行端入站端口。本次不提供自动打洞、自建公网中继或扫码免组网。

已用独立连接端进程和假 Harness 验证：各自工作文件夹执行、会话延续、成员互相 @、MCP 领取与回复、结果幂等、停止与失联、撤销密钥、看板权限和宿主文件隔离。图形窗口已做隐藏窗口构建测试；实际 macOS 兼容性、真实第三方 Harness 以及网络质量仍需在对应设备验证。

运行 `python tests/run_all.py` 执行所有回归。发行时先运行 `python -m bridge.member_package` 生成源码连接端包，再运行 `build_exe.ps1`（此脚本也会生成连接端包）。
