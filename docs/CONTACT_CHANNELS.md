# 联系人与接入渠道

## 产品模型

人和 Harness 都是平等的联系人，都可以独立成为会话成员并被 @。例如：我、我的 Codex、朋友、朋友的 Claude 是四位联系人；Harness 不是某个人下面的下级。不同类型可以具有不同能力和权限，但不改变会话成员的地位。

设备只描述连接从哪里来或任务在哪里执行。人可使用手机浏览器和电脑浏览器访问同一身份。一个 Harness 联系人先对应一个明确的运行实例；另一设备启动独立实例，即使使用同一厂商账号也应作为另一个联系人，不能自动合并。手机远程操作已有实例不产生新 Harness。设备标签不是身份凭证，网络地址也不能证明身份。

会话选择的是联系人，权限也属于会话中的联系人；渠道负责具体连接与执行，不应因为渠道切换产生新联系人或绕过会话权限。“我”的不同设备需通过可信配对关联同一身份；朋友须使用自己的身份或邀请，不能借“我的设备”接入码变成我。

## 界面

联系人显示姓名、独立 ID，其下展示当前已有接入方式和状态；远程 Harness 在线时显示设备标签。点击联系人进入现有接入配置。渠道和身份不能依据品牌或同名自动合并。现有数据只记录每个联系人的一种驱动和一份接入状态，不应呈现为完整的多渠道列表。

## 自动执行与身份

第一版保持一个 Harness 联系人对应一个自动执行端。同一身份第二个执行端在线时被拒绝；另一台设备的独立实例应添加为不同联系人。任务只交给对应成员执行，不广播给同品牌的其他联系人。

任务领取使用租约，回复须校验联系人、会话权限及租约。已领取任务遇到断网或不确定结果时不自动在另一设备重跑，以免重复修改文件或调用外部服务。联系人各有独立凭证，不同联系人撤销互不影响；密钥不得在状态接口中回显。

本机路径、Harness 的进程、配置和模型会话属于执行设备，不能假设不同设备上的工作目录或第三方会话 ID 相同；切换渠道时要显式处理上下文，不能静默将一台设备的 session ID 当成另一台设备的本地会话。

## 当前实现与迁移

当前注册表将 driver 绑定到联系人；联系人凭证及连接状态基本是一份，远程任务 Broker 同一联系人只允许一个自动执行端。联系人列表展示已有的单个接入方式，并支持在会话快捷 @ 中显示联系人名称、插入其独立 ID；这不是独立渠道管理或云端账户。

后续实现人的跨设备账户时必须保留原联系人 ID、会话成员和权限，兼容旧密钥及客户端，并测试迁移和回滚。在线信息是最近心跳，不代表人或 Harness 身份发生变化。

渠道可使用本机调用、局域网、Tailscale、已有 HTTPS 代理，未来可接公网中继；中继和邮箱云账户仍需另行实现。设计不能假定本项目已有公网服务或跨设备账户同步。
