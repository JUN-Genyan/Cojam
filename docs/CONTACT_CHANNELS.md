# 联系人与接入渠道

## 产品模型

人和 Harness 都是平等的联系人，都可以独立成为会话成员并被 @。例如：我、我的 Codex、朋友、朋友的 Claude 是四位联系人；Harness 不是某个人下面的下级。不同类型可以具有不同能力和权限，但不改变会话成员的地位。

设备只描述连接从哪里来或任务在哪里执行。渠道属于联系人：同一人可使用手机浏览器和电脑浏览器；同一个 Harness 可有多个设备或协议渠道。不同 Harness 即使来自同一设备，也保留各自独立身份。设备标签不是身份凭证，网络地址也不能证明身份。

会话选择的是联系人，权限也属于会话中的联系人；渠道负责具体连接与执行，不应因为渠道切换产生新联系人或绕过会话权限。“我”的不同设备需通过可信配对关联同一身份；朋友须使用自己的身份或邀请，不能借“我的设备”接入码变成我。

## 界面

联系人显示姓名和整体状态；其下展示接入渠道，分别显示渠道类型、设备标签、在线状态和最近连接。允许查看、添加、撤销单个渠道；离线渠道和联系人保留，不因为断网删除。界面只展示后端真实记录，不伪造渠道或在线状态。具体交互在实现时兼容现有联系人和会话。

## 自动执行与身份

同一 Harness 的多个渠道可以同时在线。每个任务只能选一个合适的在线渠道执行，不能广播给所有渠道。渠道选择应考虑是否具有任务所需能力、工作目录、用户允许的权限，以及该会话能否安全沿用该设备上的 Harness 会话；无法安全决定时要求用户选择或提示不可用。

任务领取使用原子租约，携带任务 ID 和渠道身份；回复须校验联系人、渠道、会话权限及租约。已领取任务遇到断网或不确定结果时不自动在另一设备重跑，以免重复修改文件或调用外部服务。可安全判断未执行的任务才允许重新分配。渠道各有独立凭证，可撤销某个渠道而不影响同一联系人的其他渠道；密钥不得在状态接口中回显。

本机路径、Harness 的进程、配置和模型会话属于执行设备，不能假设不同设备上的工作目录或第三方会话 ID 相同；切换渠道时要显式处理上下文，不能静默将一台设备的 session ID 当成另一台设备的本地会话。

## 当前实现与迁移

当前注册表将 driver 绑定到联系人；联系人凭证及连接状态基本是一份，远程任务 Broker 同一联系人只允许一个自动执行端。因此以上多渠道并发、逐渠道撤销和自动选路尚未实现；本文件是设计，不代表功能已可用。

实现时需为旧联系人生成默认渠道、保留原联系人 ID、会话成员和权限，兼容旧密钥及客户端；测试迁移和回滚。新增持久化模型需明确联系人 ID、渠道 ID、类型、能力、凭证摘要、设备显示名与状态；运行时状态和独立凭证应避免互相覆盖。在线信息是最近心跳，不代表人或 Harness 身份发生变化。

渠道可使用本机调用、局域网、Tailscale、已有 HTTPS 代理，未来可接公网中继；中继和邮箱云账户仍需另行实现。设计不能假定本项目已有公网服务或跨设备账户同步。
