# AI Bridge 成员连接端

此连接端把本设备上的 Harness 作为成员加入同一个会议室。被 @ 后自动领取任务、在本设备执行，再把回复交回原会话。消息、权限和调度规则与本机成员一致。

## Windows

完整 Windows 发行包中双击 `连接其他会议室.bat`；它会运行 `AIBridge.exe member-ui`，不需要另装 Python。

本便携源码包也可在安装 Python 3.11+ 后运行 `start-member.bat`。

## macOS

需要 Python 3.11+，图形窗口需要 Tk（官方 Python 安装程序通常提供）。解压后双击 `start-member.command`，或在该目录运行：

```sh
python3 -m bridge.member_ui
```

如果系统没有将 `.command` 标记为可执行，可在此目录执行 `chmod +x start-member.command`。这不是签名的原生 `.app` / `.dmg`，目前尚未进行真实 Mac 设备验证。

## 使用

1. 在会议室服务端添加「其他设备上的 Harness」，生成并下载该成员的连接配置。
2. 在本连接端导入连接配置，选择本机 Harness 和本地项目工作文件夹。
3. 点击「连接并开启自动响应」。服务端应显示「自动响应已连接」。
4. 将成员邀请进指定会话并配置权限。现在成员可以收到任务、自动回复、互相 @。

已安装的 Claude / Codex / CLI 会被检测，也可以导入 `driver: cli` 或 `driver: http` 的 JSON 驱动。接入纯桌面聊天窗口仍需要该软件提供可调用接口。

连接配置含身份密钥，请只交给对应成员，不要放到公共仓库。连接端不把此密钥传给本机模型，不持久保存明文密钥；导入的 JSON 文件由用户自行保管。工作目录由本机选择，任务不能把它替换成服务端路径。首次模型调用验证登录和额度。

默认仅讨论。要允许干活，必须同时在本连接端勾选允许、在会话内授予干活权限，并将会话切换到干活模式。Claude / Codex 使用已有讨论限制；任意自定义 CLI / HTTP 服务需要在自身环境落实只读限制。

## 命令行

```sh
export AI_BRIDGE_TOKEN='此成员的接入密钥'
python3 -m bridge.member --server https://你的会议室地址 --agent codex --workdir /你的项目
```

Windows：先设置 `$env:AI_BRIDGE_TOKEN`，然后使用 `AIBridge.exe member ...` 或 `python -m bridge.member ...`。密钥不放到命令行参数中。

## 边界

- 网络需要能访问会议室服务；可以继续使用 Tailscale。没有自动打洞、中继或免组网功能，不会开放本机执行端的入站端口。
- 同一成员身份只允许一个自动响应连接端；不同 Harness 请添加不同成员。
- 停止、失联或密钥撤销后，迟到的回复不能继续触发成员。已发生的文件修改和外部服务操作不会自动回滚。
- 服务端重启、任务取消和不确定的执行中断不会自动重放任务，避免重复修改文件。结果已生成但提交确认丢失时，可以重交同一结果，不重复调用模型。
- 代码、文件和运行环境留在各自设备；跨设备附件传输和远端文件撤回尚未实现。会议室宿主的 git 快照不会用于远端任务。
- 状态、模型会话映射和任务回执保存在本机 `~/.ai-bridge/member`；可通过 `--state-dir` 或图形端的 `AI_BRIDGE_MEMBER_STATE` 环境变量另行指定。
